Privacy policy

Effective October 26, 2026. Agent Autofill is an open-source application maintained by Lifan Chen. This policy describes the application and this product website; independently configured agents and services have their own policies.

Information the application accesses

You choose which sources to connect and which records to save. These can include profile and contact details, credentials, financial fields, email, and local Messages. Gmail access includes the connected email address, mailbox labels, message identifiers, senders, subjects, receipt times, and message content needed for your requested email tasks. The app uses Google OAuth tokens to access the account you authorize.

How Google user data is used

Gmail data is used to search and read messages and retrieve recent authentication codes for a specified recipient and task. The updated Gmail API connector in the local development build requests the gmail.readonly scope; it has not yet been released publicly. This scope still permits reading mail throughout the authorized account; the broker further limits requests to the configured mailbox and approved task. Existing public versions and legacy IMAP connections may use Google's full-mail scope, but the broker provides no send, edit, or delete operation.

Agent Autofill does not sell Google user data, use it for advertising, or use it to develop or train generalized AI or machine-learning models. Agent Autofill's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Storage and security

Saved records, source metadata, permissions, and activity metadata are stored in an encrypted database on your device. Connector credentials and OAuth refresh tokens are stored in the operating-system credential store. Access tokens and fetched Gmail messages are processed in memory; the Gmail connector does not create a persistent mailbox archive. Activity records contain operation metadata rather than message bodies or returned secret values. Local review services bind to loopback addresses, and provider connections use TLS.

Sharing with agents and other services

The maintainer does not operate a backend that receives your connected mailbox. The app communicates directly with Google to authorize and read Gmail. When you authorize a connected agent, selected message content or other requested fields are returned to that agent. If the agent uses a cloud model, that content may leave your device and be processed by the agent or model provider. Use only agents and provider configurations appropriate for the information involved and consistent with Google's Limited Use requirements, including restrictions on generalized model training. Local broker storage does not override another service's retention policy.

Sending a support email or opening a public issue shares the information you include with the maintainer and the relevant email or hosting provider. Do not include mailbox tokens, passwords, authentication codes, or private message contents in public issues.

Retention, disconnection, and deletion

Saved records and activity metadata remain on your device until you delete them. To disconnect a source, run agent-autofill source-remove SOURCE_ID; this removes its connector secret and source metadata, not messages in Gmail or historical activity metadata. You can revoke Google access in Google Account connections. Removing local configuration does not itself revoke the grant at Google. Revoke a legacy grant before reconnecting if you want to remove its broader permissions.

To remove all local application data, stop the broker, remove its configured encrypted database and associated operating-system credential-store entries, and remove any backups you control. Data already returned to a separate agent, model provider, or support service follows that service's deletion process.

This website

These product and privacy pages do not include analytics scripts or tracking cookies. GitHub Pages hosts the site and may process connection metadata under GitHub's privacy statement. The interactive demo uses synthetic information.
